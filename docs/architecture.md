# Axo-App · Architecture

## Purpose
Clean, independent starting point for Axolotl 2.0 application design and implementation.

## Principles
1. Start with actual user workflows rather than a bulk component catalog.
2. Build foundations, primitives, patterns, widgets and page layouts in that order, iterating when needed.
3. Validate one reference widget in small and large sizes before multiplying variants.
4. Keep widget outer dimensions stable through its interactive states.
5. Make light/dark, keyboard access and responsive behavior part of the component contract.
6. Do not import existing AXO-02 or axolotl-2 components unless explicitly approved.

## Planned milestones
- M1: Design brief and foundations
- M2: Core UI primitives and component documentation
- M3: One fully functioning reference widget
- M4: Responsive dashboard and workspace
- M5: Additional widgets

## Not yet configured
Storybook, automated tests, CI and deployment will be introduced deliberately in later milestones.
