06 / Společný datový model

▣ Workspace
▱ Project

▤ Page → Document Blocks

▦ Database → Records → Properties

▦ Spreadsheet → Sheets → Cells

☑ Task → Status → Due Date

↗ Relation → Source ID + Target ID

📎 Attachment → File Metadata

Database není totéž co Spreadsheet. Notion-like databáze má strukturované záznamy, vlastnosti a pohledy; Excel-like spreadsheet má adresované buňky, rozsahy a výpočetní engine. Mohou spolu komunikovat, ale nemají být násilně sloučené do jedné implementace.

Všechny důležité entity mají stabilní ID. Vazby mezi nimi se ukládají jako samostatné relace. Dokumentové bloky, záznamy i výstupy nástrojů mohou odkazovat na ostatní objekty.

Jednotlivé etapy na sebe navazují. Check-list lze v prohlížeči odškrtávat pro orientaci (stav se v tomto dokumentu trvale neukládá).

09 / Vývojová pravidla a první krok

  • Nevytvářet druhý design systém. Používat stávající Axolotl DS.
  • Nepsat vlastní rich-text ani spreadsheet engine od nuly.
  • Datovou logiku držet mimo React UI komponenty.
  • Nezačínat multi-user synchronizací bez vyřešených konfliktů a oprávnění.
  • Nezačínat AI funkcemi nebo automatizacemi před bezpečným ukládáním a obnovou dat.
  • Pracovat v oddělené větvi/prototypu, nezasahovat do aktuálního design katalogu.

10 / Jak vyvíjet Notebook a další nástroje

Rozhodnutí: hybridní, modulární vývoj. Funkce vyvíjet izolovaně, ale od začátku nad společnou architekturou Axolotlu. Nezasahovat při experimentech do produkční větve; zároveň nevytvářet samostatný repozitář pro každou utilitu.

Pořadí vývoje

  1. Stabilizovat stávající design systém a pravidla použití.
  2. Vytvořit minimální Workspace Shell a společný model dat.
  3. Vyvíjet Notebook izolovaně na vlastní testovací trase.
  4. Ověřit autosave, načítání, export a návrat po refreshi; poté integrovat Notebook.
  5. Postupně přidávat databáze, tabulky, úkoly, vazby a nástroje.
  6. Pro každý modul hlídat kompatibilitu, testy a společné služby.
Doporučený nejbližší krok

Nezačínat hned funkcemi Notebooku. Nejprve připravit malou, funkční modulární kostru v samostatné větvi tak, aby sdílela design systém, model dat a testovací prostředí. Následně implementovat první Notebook bez zásahu do produkce.
